==============================================================================
 EXPLICACION GENERAL (decir al empezar, 30 segundos)
==============================================================================

DECIR:
 "El proyecto es una aplicacion web hecha en Python con Flask que administra
  una base de datos Oracle 21c Express. Se conecta como SYSDBA con la libreria
  oracledb y ejecuta las mismas sentencias SQL que un DBA haria a mano, pero
  con una interfaz. Para respaldos usa Data Pump (expdp/impdp). Tiene 8
  modulos: tablespaces, seguridad de usuarios, auditoria, respaldos,
  recuperacion, archivos de respaldo, performance y tuning. En cada uno voy a
  hacer la accion en la app y la voy a comprobar en SQL*Plus para demostrar
  que es real."

ESTRUCTURA (si la pregunta):
 - app.py            -> menu y pantalla de inicio
 - db.py             -> conexion a Oracle
 - modules/*.py      -> un archivo por modulo (la logica)
 - modules/datapump.py -> ejecuta expdp/impdp en segundo plano
 - templates/        -> pantallas HTML
 - sql/              -> scripts de verificacion por modulo
 - docs/             -> manual de usuario y guion

DECIR:
 "Los respaldos usan Data Pump: la app arma el comando expdp y lo ejecuta en

  por tabla o la base completa, y cada operacion queda registrada en el

SQL (Ventana A):

   COL directory_path FORMAT A70
   SELECT directory_name, directory_path FROM dba_directories WHERE directory_name='BACKUP_DIR';

--- 6A. Recuperar una tabla borrada ---

SQL (Ventana A) - simular el desastre:

   DROP TABLE usr_demo.t1;

 -> Da error ORA-00942 (la tabla ya no existe).

   Modo                : TABLE

 9. TUNING DE CONSULTAS                                          ~3 min
==============================================================================

DECIR:
 "El tuning busca que las consultas lentas sean rapidas. Oracle decide como
  buscar los datos con un plan de ejecucion. Voy a explicar una consulta sobre
  una tabla de 200 000 filas: sin indice hace un FULL SCAN, o sea, lee toda la
  tabla; despues creo un indice y el plan pasa a INDEX RANGE SCAN con un costo
  mucho menor."

APP:  Menu -> Tuning de consultas.

--- 9.1 Plan SIN indice ---
   Esquema  : USR_TUNING
   Sentencia: SELECT * FROM ventas WHERE cliente = 42
   -> Pulsar "Explicar plan" (no ejecuta la consulta, solo muestra el plan).
   Resultado esperado: TABLE ACCESS FULL. ANOTAR EL COSTO.

SQL (Ventana A) - mismo plan por SQL*Plus:

   EXPLAIN PLAN FOR SELECT * FROM usr_tuning.ventas WHERE cliente = 42;
   SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);

--- 9.2 Crear el indice ---
APP:  Pestana Indices -> Crear:
   Tabla: VENTAS     Columna: CLIENTE     Nombre: IDX_VENTAS_CLIENTE
   (tipo normal, no UNIQUE)

SQL (Ventana A):

   SELECT index_name, table_name, uniqueness, status FROM dba_indexes WHERE owner='USR_TUNING';

--- 9.3 Plan CON indice ---
APP:  Volver a "Plan de ejecucion" y explicar la MISMA sentencia.
   Resultado esperado: INDEX RANGE SCAN y costo MENOR. La app muestra la
   comparacion con el plan anterior ("el costo mejoro").
   Tambien probar "Ejecutar y medir" para ver el tiempo real.

SQL (Ventana A):

   EXPLAIN PLAN FOR SELECT * FROM usr_tuning.ventas WHERE cliente = 42;
   SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);

--- 9.4 Estadisticas ---
DECIR:
 "Las estadisticas son los datos (filas, bloques) que Oracle usa para elegir
  el mejor plan. Si estan obsoletas, el optimizador puede elegir mal."

APP:  Pestana Estadisticas -> esquema USR_TUNING: ver filas, bloques, ultimo
      analisis y si estan obsoletas. Pulsar "Recolectar" (tabla o esquema).

SQL (Ventana A):

   SELECT table_name, num_rows, blocks, TO_CHAR(last_analyzed,'HH24:MI:SS') analizada
   FROM dba_tables WHERE owner='USR_TUNING';

 -> num_rows = 200000 y la hora de ultimo analisis se actualiza.
    (Si ya decia 200000 antes de recolectar, es normal: Oracle recolecta
     estadisticas solo al crear la tabla; lo que cambia es la hora.)

APP:  Pestana Indices: mostrar columnas, estado y uso; probar "Reconstruir".

==============================================================================
 SI ALGO FALLA EN VIVO (calma, ya esta previsto)
==============================================================================

* Cuadro rojo ORA-01017 en el Inicio
    -> contrasena mal en el archivo .env. Corregir, Ctrl+C en la terminal y
       volver a correr  python app.py.

* Un respaldo sale en ERROR
    -> abrir "Ver log" y leer el mensaje. Verificar que expdp funciona
       (expdp -help) y que existe el directorio BACKUP_DIR.
    -> Si el log dice "terminado correctamente" pero el estado es ERROR,
       falta aplicar el arreglo del paso 0.2.

* "Archivo de respaldo invalido" en Recuperacion
    -> elegir un archivo de la lista del selector; los nombres cambian con
       cada respaldo nuevo (fecha y hora).

* La recuperacion por tabla termina "OK" pero no cambia nada
    -> la tabla ya existia y la opcion era SKIP. Borrar la tabla antes
       (DROP TABLE usr_demo.t1;) o elegir REPLACE.

* El UPDATE de la Ventana C no se queda esperando
    -> la Ventana B hizo COMMIT o no ejecuto el UPDATE. Repetir el paso.

* Los registros de auditoria no aparecen
    -> ejecutar  EXEC DBMS_AUDIT_MGMT.FLUSH_UNIFIED_AUDIT_TRAIL;  y
       refrescar la pantalla. Revisar que la politica este habilitada
       para USR_DEMO y que te reconectaste DESPUES de habilitarla.

* Un error raro de la app
    -> la app muestra una pantalla de error con el mensaje de Oracle; no es
       un cierre. Leerlo, explicarlo y volver con el menu.


==============================================================================
 PREGUNTAS PROBABLES DEL PROFESOR (respuestas cortas)
==============================================================================

- Por que conecta como SYSDBA?
  Porque administra tablespaces, usuarios, auditoria y Data Pump; se usa
  solo en un entorno de laboratorio.

- Por que los respaldos corren en segundo plano?
  Para que la interfaz no se bloquee; un hilo ejecuta expdp/impdp y al
  terminar actualiza el historial (SYSTEM.BKP_HISTORIAL).

- Como sabe la app si un respaldo salio bien?
  Por el codigo de salida de expdp/impdp: 0 = OK, 5 = con advertencias,
  otro = ERROR; y muestra el log completo.

- Que es un DIRECTORY de Oracle?
  Un objeto que apunta a una carpeta del servidor; Data Pump solo escribe
  ahi (aqui BACKUP_DIR).

- Que diferencia hay entre respaldo por schema, tabla y full?
  Schema = todos los objetos de un usuario; tabla = solo esas tablas;
  full = toda la base de datos.

- Que hace el remap?
  Restaura los objetos de un usuario bajo otro nombre (USR_DEMO -> USR_COPIA),
  sin tocar el original.

- Por que sirve un indice?
  Evita leer toda la tabla (FULL SCAN): Oracle va directo a las filas que
  coinciden (INDEX RANGE SCAN), con menor costo.

- Que es la auditoria unificada?
  Un sistema unico de Oracle donde las politicas definen que acciones se
  registran y todo queda en UNIFIED_AUDIT_TRAIL.

- Como evita la app borrar cosas por error?
  Pide confirmaciones escribiendo el nombre (tablespace), LIMPIAR (auditoria)
  o FULL (recuperacion total), y protege los objetos del sistema.
